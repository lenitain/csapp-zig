# Malloc Lab

**对应章节：** 第九讲（虚拟内存）

**一句话点题：** 内存分配器就是在堆上管理空闲块和已分配块的数据结构。

## 为什么要做这个实验

CSAPP 的 Malloc Lab 让你实现 `malloc`、`free`、`realloc`——用户空间的内存分配器。

在 AI 时代，手写 malloc
的价值趋近于零——成熟的分配器（jemalloc、tcmalloc）已经优化了几十年。但实验传达的**核心 insight**
仍然重要：

**内存分配器是一个数据结构问题。**
你怎么组织空闲块？怎么快速找到合适大小的块？怎么合并相邻的空闲块？这些问题和链表、哈希表、树是同一类问题。

## 分配器的核心接口

```c
void *malloc(size_t size);    // 分配 size 字节
void free(void *ptr);         // 释放之前分配的内存
void *realloc(void *ptr, size_t size);  // 调整大小
```

底层是操作系统提供的 `sbrk()` 或 `mmap()`。分配器在这些大块上做细粒度的管理。

## 最简单的分配器：隐式空闲链表

### 块格式

```text
+--------+--------+--------+--------+
| 头部   | 负载   | ...    | 填充   |
+--------+--------+--------+--------+
```

头部记录块的大小和是否已分配（用最低位表示）。

### 分配策略

**首次适配 (First Fit)**：从头遍历空闲链表，找到第一个足够大的块。

```c
void *first_fit(size_t size) {
    char *bp = heap_start;
    while (GET_SIZE(HDRP(bp)) > 0) {
        if (!GET_ALLOC(HDRP(bp)) && GET_SIZE(HDRP(bp)) >= size) {
            return bp;  // 找到了
        }
        bp = NEXT_BLKP(bp);
    }
    return NULL;  // 没找到
}
```

### 思路

隐式空闲链表的"链表"不是真的有 next/prev
指针——块在内存中是连续的，通过块头部的大小字段可以计算下一个块的位置。

**分配时**：遍历找到合适的空闲块，可能分割（如果块太大）。
**释放时**：标记为空闲，可能合并相邻的空闲块。

### 缺点

每次分配都要遍历整个堆，O(n) 时间。对于大堆，这很慢。

## 更好的方案：显式空闲链表

### 块格式

```text
+--------+--------+--------+--------+--------+
| 头部   | 前驱   | 后继   | 负载   | ...    |
+--------+--------+--------+--------+--------+
```

空闲块额外存储前驱和后继指针，形成双向链表。已分配块不需要这些字段。

### 思路

显式空闲链表只遍历空闲块，不遍历已分配块。如果堆里大部分内存已分配，显式链表快得多。

**核心 insight：数据结构的选择影响性能。**
同样的问题（管理空闲块），不同的数据结构（隐式链表 vs 显式链表 vs
分离空闲链表）有不同的性能特征。

## 进一步优化：分离空闲链表 (Segregated Free Lists)

### 思路

不同大小的块用不同的链表：

- 0-16 字节的空闲块 → 链表 A
- 17-32 字节的空闲块 → 链表 B
- 33-64 字节的空闲块 → 链表 C
- ...

分配时直接去对应大小的链表找，不用遍历所有空闲块。

这是 glibc 的 `ptmalloc` 和 jemalloc 使用的策略。

## Zig 的 Allocator 接口

```zig
// Zig 的分配器是接口，不是全局函数
const allocator = std.heap.page_allocator;
const data = try allocator.alloc(u8, 1024);
defer allocator.free(data);
```

Zig 的 `Allocator` 是一个接口，不同的实现有不同的策略：

- `page_allocator`：直接调用 mmap，最简单
- `GeneralPurposeAllocator`：类似 glibc 的 malloc，有调试功能
- `ArenaAllocator`：只分配不释放，最后一次性释放

**核心 insight：Zig 把"用什么分配器"的决定权交给了程序员，而不是藏在标准库里。**
你可以根据场景选择最合适的分配器。

## 本实验的 takeaway

1. 内存分配器是堆上的数据结构问题
2. 隐式空闲链表简单但慢（O(n) 遍历整个堆）
3. 显式空闲链表只遍历空闲块，更快
4. 分离空闲链表按大小分组，进一步提速
5. Zig 的 Allocator 接口让分配策略可替换

**核心 insight：malloc
不是魔法，它是一个工程问题——在分配速度、释放速度、碎片率之间找平衡。理解这个，你就能理解为什么"频繁
malloc/free 会变慢"以及"为什么 arena 分配器在某些场景下快得多"。**
