# Data Lab

**对应章节：** 第二讲（数据表示）

**一句话点题：** 位运算是一套完备的计算基础——加法、条件判断、类型转换都能用位运算完成。

## 为什么不手写位运算 hack

原 CSAPP Data Lab 让你用 ~, &, ^, |, <<, >>, !, + 实现各种函数，不能用 if、循环、乘除。

**AI 时代这件事的价值趋近于零**——让 LLM 写 `is_equal(x, y) = !(x ^ y)` 是几秒钟的事。
重点不是"会写"，是"看了之后能解释为什么"。

## 核心 insight

**位运算是完备的计算基础。**

- 加法 = 异或 + 与
- 乘法 = 移位 + 加法
- 条件判断 = 位掩码
- 类型转换 = `@bitCast` 或 memcpy

**为什么重要？因为 CPU 的 ALU 就是这么做的。** 加法器是基本门电路，移位器是连线，逻辑门组
合起来就是 ALU。知道 CPU 能做什么，你就知道为什么软件能优化。

## AI 帮你做什么

**让 AI 解释每个位 hack 的数学。**

```c
// 经典题目：只用 ~, &, ^, |, <<, >>, !, + 实现 is_equal(x, y)
```

让 LLM 解释：

1. `x ^ y` 在 `x == y` 时为什么是 0？
3. 为什么 `!0` 是 1 而不是 0？这是 C 的 boolean 约定。

**让 AI 解释补码的取正/取负。**

```c
// 经典题目：用位运算实现 negate(x) = -x
// 答案是 ~x + 1
```

让 LLM 解释：

1. 为什么 `~x + 1` 等于 `-x`？这是补码的数学性质
2. 如果是 8 位，`~0 + 1` 是多少？这要解释 wrap-around
3. `INT_MIN` 取负为什么有问题（`-INT_MIN` 还是 `INT_MIN`）

**让 AI 解释无分支绝对值。**

```c
int abs_val(int x) {
    int mask = x >> 31;
    return (x ^ mask) + (~mask + 1);
}
```

让 LLM 解释：

1. `x >> 31` 在 x 是负数时为什么全 1？算术右移
2. 为什么 `x ^ mask` 在 mask 全 1 时是 `~x`，全 0 时是 x？
3. `~mask + 1` 在 mask 全 1 时是 -1，全 0 时是 0——为什么？

**让 AI 解释 float 的位表示。**

```c
unsigned float_bits(float f) {
    unsigned bits;
    memcpy(&bits, &f, 4);
    return bits;
}
```

让 LLM 解释：

1. 为什么不能用 `*(unsigned *)&f`？严格别名规则
2. memcpy 怎么被优化成零开销？编译器优化
4. 为什么要看 float 的位？IEEE 754 标准布局

## 你应该能回答的判断题

**不**：
1. "is_equal(x, y) = !(x ^ y)"——为什么 x ^ y 是 0 时相等？答：因为相同位的异或为 0。
2. "用位运算实现 abs_val(int x)" 的步骤是什么？答：mask = x >> 31；如果 mask 全 1，x ^ mask = ~x，加 (~mask + 1) = -1，变成 ~x - 1 = -x；如果 mask 全 0，加 0，保持 x。
3. "float 怎么转成位级表示？" 答：memcpy 是正确的；强转违反严格别名。
4. "为什么 `x + 1` 在 x = INT_MAX 是 UB？" 答：有符号溢出是 UB。

## 本实验 takeaway

1. 位运算能做什么？答：一切——加法、条件判断、类型转换。
2. 补码取负的数学是什么？答：~x + 1 = -x。
3. memcpy vs 强转的差别？答：严格别名规则。
4. 在 AI 时代意味着什么？答：让 LLM 写，你理解。

**核心 insight：位运算是 ALU 的语言。理解它，你才能读懂编译器的优化。**
